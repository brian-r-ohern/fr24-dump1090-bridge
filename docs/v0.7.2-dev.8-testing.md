# v0.7.2-dev.8 — analytical GeoJSON and proximity usability

Public v0.7.1 remains the stable baseline. Development preview dated 2026-10-21.

## Changes and exact semantics

### One downloadable history format

Export selected and Export all download `aircraft-analysis-history.geojson.gz`.
The interactive selected-history request remains schema-1 JSON, so map trail
polling does not download an entire GIS wrapper. No second export-format choice
is presented. Density and range-coverage formats are unchanged.

A FeatureCollection contains one Feature per retained track. `history_metadata`
contains every original collection field except `tracks`, including the full
motion snapshot, provenance, source, build, and retention limits. Each feature's
`properties.record` contains the complete original track object, including
identity, timestamped samples, missing values, nested diagnostic evidence, and
unknown future fields. `properties.track_id` preserves its dictionary key.
Flattened flight, ICAO, origin/destination, source, sample count, and start/end
epoch times provide convenient GIS attributes. `history_geojson_version=1`
identifies this reversible wrapper. `history_from_geojson` reconstructs the
original analytical payload. Mapping geometry is derived, not authoritative.

Geometry uses WGS84 longitude/latitude, without a Z coordinate: original altitude
values, units, references and timing remain in the records. Runs split on segment
change, break_reason, intervals exceeding 30 seconds, nonincreasing timestamps,
invalid coordinates, or antimeridian crossing. MultiLineString represents line
runs; MultiPoint retains isolated valid observations. Mixed runs use a
GeometryCollection; empty/no-valid-position tracks have null geometry but retain
their record. Other GIS software may simplify or discard nested attributes on
resave: lossless reconstruction applies to the bridge export itself, not an
arbitrary GIS round trip.

QGIS: extract the gzip file, add its `.geojson` as a vector layer, and label/filter
using the flat properties. Mixed geometries may be exposed as separate geometry
layers depending on the GIS reader. No actual QGIS run was available here.
Both offline replay tools accept this wrapper and legacy JSON/gzip. ZIP input
accepts exactly one `.json` or `.geojson` member.

### Selected reference, slant range and closure

The panel summary and result heading identify the selected callsign and reported
ICAO; the local track key is the fallback. The existing 20 NM **horizontal** search
radius and stale-data gates remain. Compute current approximate slant range as
`sqrt(horizontal_metres^2 + (vertical_feet * 0.3048)^2) / 1852` using the existing
common source timestamp and matching-altitude-field gates. This is an altitude-
based geometric estimate, not a measured line-of-sight range. Barometric altitude
uncertainty and reference limitations still apply. Missing comparable altitude
produces Unknown, never zero.

Sort all eligible candidates by known slant range before taking the nearest ten.
Unknown slant ranges follow, sorted by horizontal distance. The Closure column
replaces Trend and displays Closing/Opening plus absolute horizontal range-rate
in knots; Nearly steady uses the existing +/-0.5 m/s deadband. Unknown velocity
remains Unknown. Horizontal CPA/TCPA and vertical separation at that horizontal
CPA retain dev.7 semantics; no 3D CPA or slant closure model is introduced.

### Feed recovery

The map checks status source changes before treating an obsolete raw-feed 403 as
a data failure. A source change reloads the map into the correct rendering mode;
both SBS-to-FAA and FAA-to-SBS are covered. Source changes within either mode also
reload after the initial source has been learned. Network failures still retry
through normal map refreshes; no access-control bypass is added.

The SBS reader now maintains a 60-second successfully parsed MSG watchdog in
addition to the 60-second byte-idle watchdog. STA/status or malformed traffic does
not reset the aircraft-message timer. On timeout the socket context closes and
the existing two-second reconnect loop runs. The timer starts at connection time;
an actually quiet receiver can therefore reconnect once per roughly minute even
if the TCP session is otherwise healthy. No receiver settings are changed.

  GeoJSON reconstruction, unknown fields, empty/isolated tracks, breaks,
  antimeridian handling, slant selection before limit, reciprocal values,
  valid-message resets, and status-only watchdog expiration.
