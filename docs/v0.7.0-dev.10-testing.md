# v0.7.0-dev.10 validation

Upgrade the existing local App and retain verbose logging. This remains a development build preceding the public v0.7.0 release.

## Automatic cached density

1. Enable density and load Fit aircraft. Zoom/pan, load another view, then return to Fit aircraft. Once movement settles (200 ms debounce), fully cached fresh tiles should display automatically without pressing Load density. Expect cache hits and zero aggregated SQL rows in logs.
2. Visit an uncached view or choose an uncached altitude combination. It should indicate Load density needed and retain the previous layer until a manual load. The displayed cell count/time still describe the old layer while pending.
3. Leave tiles past two hours or clear/import data. Stale/missing tiles must not trigger an automatic rebuild. Press Load density to build them; Refresh now bypasses valid cached tiles too.
4. A cache-only request is rechecked atomically under the store lock. Missing/expired/noncacheable views return HTTP 409 without querying observations or building rollups. FAA local viewer HTML follows the same contract; general FAA density outputs remain blocked.

## Speed diagnostics

1. Enable verbose logging, save/restart, and hard-refresh the map. Open a level, stable-course aircraft and expand Speed diagnostics. Find derived speed min/median/max, range, fit residual, trend, accepted position interval min/median/max, reported-speed comparison and stable-speed blockers.
2. SBS and aircraft.json label reported ground speed. SFDPS labels reported speed with unverified meaning; its speed field does not drive motion detection. A latest-leg average minus a latest reported value is descriptive and may combine different time supports/quantities.
3. Blockers can overlap: on ground, too few position samples, insufficient position span, too few usable speed samples, insufficient speed span, unavailable fit, excessive fit residual, excessive speed variation, or speed trend. A small displacement is excluded from usable speed legs by the existing 25 m floor. Independent observations, not retained duplicate snapshots, define intervals.
4. Existing stable-speed criteria remain: adequate position/usable-leg support; OLS residual <=8 kt; max-minus-min speed <=10 kt; absolute trend <0.1 kt/s. SFDPS's existing motion-span gate is 55 seconds between usable-leg midpoints, so six reports spanning 60 seconds may still need an additional report before speed classification. No thresholds are loosened in this build.
5. Capture a popup for cruise-like SFDPS examples and a verbose Motion diagnostics entry. Aggregate logs summarize fresh tracks, speed blocker counts, speed/difference distributions, per-track range/residual/trend and accepted interval medians. They omit aircraft identifiers, coordinates, callsigns and routes. Stale tracks are excluded. Turning/accelerating aircraft should continue showing their normal labels.
6. Disable verbose logging and restart/reload: popup speed details and extra diagnostic logs disappear. Normal motion summaries remain; density and motion detection are unchanged.
