# v0.7.0-dev.4 — Larger aircraft and local SFDPS view

This development build follows dev.3. The first public motion release remains v0.7.0.

## Aircraft markers

Aircraft SVG display size increases from 24 × 24 to 36 × 36 screen pixels (1.5× each dimension). Leaflet marker size is also 36 × 36 and its anchor changes from 12,12 to 18,18. The SVG viewBox remains 24 × 24; changing the viewBox would alter the artwork rather than its display size. Motion colors, military styling, closest glow and O/D badges remain available. Home icons are unchanged.

## Configure SFDPS

1. Select `source: swim_sfdps` in App Configuration.
2. Enter the FAA-authorized **SFDPS** Solace broker host, message VPN, subscription username/password and durable queue/JMS name in the existing `swim_*` fields. A TFMS queue is not an SFDPS queue.
3. Save and restart the App. The input source selects the parser/product automatically; the legacy `swim_product` field cannot override it.
4. Home Assistant Home must be available. Until then, messages are counted but no aircraft positions are retained. `swim_radius_nm` applies to observed positions, with the existing 250 NM default.
5. Open the Web UI. Its title/card identifies **FAA SFDPS · local view**. Full four-letter airport identifiers match native route O/D codes, e.g. `KSYR`.

SFDPS is a mutually exclusive local-view source. No SFDPS density store is opened or migrated; collection, backups/imports, GeoJSON, density envelopes and motion analysis are disabled. Existing ADS-B/TFMS density and ADS-B range files are preserved. Switch back to the corresponding source to use its history. SFDPS does not gain destination ETA modeling in this increment.

## FAA isolation

`/aircraft.json` and `/data/aircraft.json` return **403** for **both TFMS and SFDPS**, including requests carrying `client_id`. The existing code previously served TFMS there; dev.4 closes that output. Track-history proxy and density JSON/GeoJSON exports/envelope APIs also reject FAA-source requests. Range processing and exports remain disabled for FAA sources. ADS-B source endpoints are unchanged.

The local map refreshes its own HTML document every five seconds and consumes escaped, in-memory display state embedded in that document. It does not use a separate FAA aircraft feed endpoint. TFMS density likewise refreshes bounded recent display geometry through that HTML view; its generic density JSON/GeoJSON endpoints are closed. Local visualization necessarily delivers display information to the viewer's browser; this is not an authorization mechanism, and the direct LAN Web UI remains unauthenticated. Keep it local. Do not publish FAA captures, display state or derived datasets. No captured FAA data is bundled in this release or its test fixtures.

TFMS retains its existing local density collection/view; SFDPS has no density in dev.4. The dashboard integration consumes status counters, not FAA aircraft records. External ADSB Tracker enrichment/history lookup is disabled for FAA views; their native route metadata remains visible.

## Parser and continuity contract

The first adapter supports the FIXM 3.x MessageCollection/flight structure in the supplied SFDPS capture. Namespace prefixes are irrelevant; field scope is explicit:

| Meaning | Field / rule |
| --- | --- |
| Observed position | `flight/enRoute/position/position/location/pos`, EPSG:4326, latitude then longitude |
| Observation time | Parent `position/@positionTime`, timezone-qualified |
| Evidence | Parent `position/@reportSource = SURVEILLANCE` |
| Observed altitude | Direct child `altitude`, `uom=FEET`; never assigned/target altitude |
| Reported speed | `actualSpeed/surveillance`, `uom=KNOTS`; displayed as reported speed |
| Flight occurrence | `gufi`; a callsign alone is insufficient |
| Callsign | `flightIdentification/@aircraftIdentification` |
| Native route | `departure/@departurePoint`, `arrival/@arrivalPoint` |
| Optional reported ICAO | Supplemental `ADSB_02M_52B`, only a valid six-digit hexadecimal value |
| Course | Derived from successive observed positions/timestamps; no unverified velocity-axis conversion |

`targetPosition`, `targetAltitude`, route waypoints and assigned altitude never substitute for an observed position/altitude. Non-surveillance reports, unsupported CRS, invalid coordinates, missing GUFI, unqualified time and malformed XML are rejected or omitted as appropriate. Unrecognized altitude/speed units are omitted. The reported altitude reference and reported-speed semantics are not promoted into validated ADS-B motion inputs.

SFDPS position times more than `swim_aircraft_timeout` seconds old or more than five seconds in the future are excluded at admission. Equal/older position updates do not replace a newer track or extend its receipt timeout. Aircraft expire after the configured receipt timeout; the in-memory view is capped at 4,096 flight occurrences, evicting the least recently accepted track at capacity. Source-local hashed GUFI identifiers are distinct from actual ICAO addresses. Private GUFIs are not inserted into browser display state, diagnostics or logs.

The shared course estimator needs distinct time-ordered positions, no more than 300 seconds apart, at least 0.05 NM displacement and implied speed no greater than 1,200 kt. A stationary update may retain the previous course. This is a map orientation estimate, not the motion-analysis engine.

Browser-engine visual automation is unavailable here; check the live UI.

Live checks: larger icons centered while turning; native O/D and route metadata; first update may have unknown course, second moving update gains course; source/product/status counters; no Density/range/motion controls; FAA feed URLs return 403; switching back to SBS recovers its normal feed and existing history.
