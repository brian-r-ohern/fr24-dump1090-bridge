# v0.7.0-dev.12 theme verification

1. Upgrade normally. An installation without map_theme defaults to auto. Confirm `/map-config` reports map_theme: auto.
2. Set light in App Configuration, save/restart, then hard-refresh the map. Check the light basemap irrespective of browser preference.
3. Set dark, save/restart/reload. Check readable dark basemap tiles; aircraft colors, closest glow, O/D badges, density scale, range/envelope lines and popups retain their own styling.
4. Set auto and change the browser/device light/dark preference. The basemap changes without restarting collection. Auto follows that preference, not an independently selected HA frontend theme.
5. Save/restore settings and confirm the mode survives. Older snapshots without the field restore as auto. Unsupported values are rejected. No collected data migration or new tile provider is involved.
6. Check density auto loading/forced refresh, motion filters, ETA popups and Fit aircraft after each palette change.

Validation: 130 Python tests and shipped JavaScript checks, including defaults/enum rejection, snapshot persistence, initial HTML and map-config for SBS/SFDPS, preference change events, explicit overrides and basemap-only filter targeting. Live visual readability requires a check on the user's Home Assistant/browser.
