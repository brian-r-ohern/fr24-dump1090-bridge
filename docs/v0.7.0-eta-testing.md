# Destination ETA preview validation

Build: 0.7.0-dev.1, based on released 0.6.9.3. No motion detectors or persistence migration.

## Automated checks

Python tests exercise bundled IATA/ICAO matches, ambiguous identifiers, invalid coordinates, bounded HTTP lookups, dataset failure isolation and unchanged feed/consumer accounting. The Node check exercises real map code for distance/time calculation, UTC midnight rollover, antimeridian geometry, missing/invalid speed or destination, ground exclusion, popup rendering, lookup caching and retry behavior.

Validation on October 10, 2026: the existing suite plus airport lookup/HTTP tests passed (70 tests); the additional CSV conversion test also passed. Node ETA, dashboard-card and density-control checks and complete map-script syntax checks passed. All 29 user-supplied CSV sample records match the pinned full snapshot.

## Live Home Assistant checks

1. Back up settings and both collected datasets, install the preview, and confirm `/status` reports 0.7.0-dev.1 and the selected feed reconnects.
2. On ADS-B with Tracker enrichment, open an aircraft with a known destination and positive ground speed. Confirm distance, approximate duration and UTC arrival time. Compare one estimate with distance / knots × 60.
3. On TFMS, confirm a four-letter arrival identifier such as KJFK resolves without Tracker enrichment. Confirm sparse reports do not imply a route-based ETA.
4. Confirm unknown destinations, unavailable/zero speed and explicitly ground aircraft omit the estimate. Aircraft and existing metadata should still display.
5. Pan/zoom and select additional aircraft; airport lookup requests should fetch only previously unseen codes. A failed lookup should leave the map usable and retry after 30 seconds.
6. Confirm existing range/density datasets, exports, dashboard card and normalized aircraft feed remain available. The feature adds no fields to aircraft.json.

Live HAOS behavior remains to be confirmed by the user. The preview uses current speed, not filed speed, scheduled arrival or route length. CSV processing happens during preparation, never during App startup.
