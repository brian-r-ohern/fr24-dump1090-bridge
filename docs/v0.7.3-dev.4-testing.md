# v0.7.3-dev.4 testing

Hit **Ctrl+Shift+R** before updating. Refresh Configuration after the first app start.

## Layout

The first fields are Input source, Receiver IP address or hostname, and an optional airport highlight. SBS requires only the receiver address. Personalization and Integrations follow. Additional local feeds contains legacy FR24 HTTP and aircraft.json settings; FAA SWIM contains subscription credentials and gate. Developer / troubleshooting holds the history URL, recording visibility, logging, trusted networks, timing, entity overrides and legacy density attribution.

## Upgrade behavior

Startup reorganizes existing valid options using Supervisor's API. Flat values override new group defaults during migration. The migration retrieves unrendered options from Supervisor to preserve `!secret` references. It does not overwrite `/data/options.json`. Failure logs a credential-free warning and flat runtime compatibility remains available. Settings backups remain readable; explicit restore writes grouped options with the existing confirmation flow. Port exposure settings stay separate.

Compatibility-only flat aliases may appear under Home Assistant's Show unused optional configuration options; use the grouped fields for new edits. The SWIM product alias is compatibility-only, since Input source chooses the product.

## Coverage and limitations

Automated tests cover flat/grouped equivalence for all five sources, legacy precedence, malformed group rejection, secret-reference preservation, layout/default consistency and settings recovery. Existing Python and map regression checks also run. Native Configuration rendering and actual Supervisor migration require live HAOS confirmation; API tests use mocked responses.
