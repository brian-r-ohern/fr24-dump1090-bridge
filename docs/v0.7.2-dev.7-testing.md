## SBS recovery

The reported fault was an established TCP/30003 session staying silent after internet connectivity returned, while a new Ncat connection delivered messages. This supports recovery of a stale receiver-side session; it does not prove why receiver software stopped forwarding.

The reader uses monotonic elapsed time since the most recently received bytes. After 60 seconds of silence, a five-second socket-timeout check raises an idle error, closes the connection through its context manager and enters the existing two-second reconnect loop. EOF and socket errors follow that loop too. Bytes reset the idle timer even if a line does not parse; the timer does not depend on positioned aircraft or valid MSG records. An unterminated buffer larger than 1 MiB also triggers reconnect. Existing connection-attempt/reconnect counters and error logs expose recovery. A legitimately quiet receiver can therefore reconnect once per idle interval. No receiver or FR24 configuration is modified.

Synthetic checks exercise byte-timer reset, timeout and EOF, and the complete reader transition from a timed-out first socket to processing a message on a second socket. Live check: interrupt network connectivity, restore it, then confirm idle/reconnect log and resumed SBS messages without restarting the app. A receiver that still rejects fresh connections cannot be repaired by this logic.

## Using the panel

Expand **Proximity / CPA · selected aircraft**, check **Show nearby aircraft**, and click an aircraft. Refresh cadence is five seconds. The panel shows the nearest ten qualifying tracks within 20 NM, ranked by current horizontal separation. The 20-NM radius and ten-row limit are display/processing bounds, not collision or separation thresholds. No alert colors, collision warnings or notifications are produced. Selection changes clear prior results; request revisions prevent a late prior-selection response from overwriting the new selection.

Columns: aircraft, horizontal separation, vertical separation, closing/opening/nearly-steady trend, horizontal CPA/TCPA within the window, predicted vertical separation at that same instant, and model quality. Unknown altitude is shown as Unknown, never zero. Maneuvering lowers model confidence explicitly; labels are not calibrated probabilities. The panel is enabled for SBS, aircraft.json and SFDPS. TFMS and flights.js return an excluded-source explanation because of cadence/precision limits. It uses the existing sampled analytical history, so startup needs history to accumulate.

## Calculation and limits

- Observations are independent retained samples, normally at least ten seconds apart. Use only latest segment, last 90 seconds, at least three samples over 20 seconds to fit each local horizontal velocity by least squares. Reset segments prevent fitting across occurrence changes, discontinuities and gaps. Speeds above 1,500 knots are rejected.
- For SFDPS, use fitted ground-track direction scaled by the latest reported ground speed when finite/plausible. Other supported sources use fitted position-derived ground velocity. Thus this model follows the established FAA reported-speed choice.
- Freshness: 45 seconds for SFDPS, 15 seconds for SBS/aircraft.json. Both tracks must be fresh. Align to the newer of their source-position timestamps by extrapolating the older position with fitted velocity; do not extrapolate onward to wall-clock now. Display source ages/alignment in the analytical API. Unequal-time pairs without sufficient velocity are withheld; simultaneous pairs can still show separation while velocity warms up.
- Use a local east/north plane and wrapped longitude. Relative position r and velocity v give unconstrained time `−dot(r,v)/dot(v,v)`. If negative, closest approach has already passed; future CPA is unavailable. Relative speed below 0.5 m/s suppresses unstable TCPA. Closing/opening uses range rate with a 0.5 m/s deadband.
- Bound prediction to 300 seconds. If unconstrained CPA lies farther away, report **Window end** distance at 300 seconds, not a claimed CPA within the window. Otherwise report predicted horizontal CPA and seconds to it. This is horizontal CPA; vertical separation is evaluated at that same time, not a separate 3D closest-point optimization.
- Compare altitude only when both latest samples use the same field: barometric preferred, geometric fallback. Do not mix fields. Fit vertical rate from numeric same-segment observations with the same support requirements. If an older altitude cannot be aligned due to missing vertical rate, aligned vertical separation is Unknown. Missing vertical rate also makes predicted vertical separation Unknown. Rates above 10,000 ft/min magnitude are rejected. Same field is not proof of identical pressure datum or sensor accuracy.
- Recent turning, acceleration/deceleration or active geometry marks the constant-velocity assumption as lower confidence. This initial model does not extrapolate turns or acceleration. No flight intent, cleared altitude or separation minima are inferred. Short-horizon constant velocity can fail during maneuvering.

`/aircraft-proximity?track_id=<local-id>` returns selected analytical results only. It requires one valid identifier and the existing trusted-network boundary. It does not enable `/aircraft.json`, `/data/aircraft.json`, external history or generic FAA motion polling. No all-pairs feed is introduced. The history view omits verbose per-observation diagnostics and pair processing is linear in retained track count for one selection.

## Replay and verification

`python tools/replay_proximity.py recording.json.gz --track EIN107 -o proximity-replay.json`

JSON/gzip/single-JSON ZIP inputs are supported. Select one local identifier or unique callsign. Process observations chronologically, group equal source timestamps, and evaluate when the selected track updates. Never use later observations to classify earlier frames. This is a sampled replay, not a reconstruction of every live polling instant and not independently labelled encounter truth.
