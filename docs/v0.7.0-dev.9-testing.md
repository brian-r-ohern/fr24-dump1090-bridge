This is a local development build, not the public v0.7.0 release. Keep verbose logging enabled for these tests. Existing range and source-separated density histories survive an ordinary upgrade; export ADS-B backups before destructive lifecycle tests.

## Density controls and cache state

1. Enable Traffic Density. It loads without a second button press. Check the compact `30 days · All Traffic · … cells · As of … · … cached / … to build / … stale` summary. First parent-grid backfill can still take time.
2. Pan or zoom and change altitude bands. The old layer stays visible and is marked `Load density needed`. Tile counts describe the requested view, while cell count/As of describe the displayed layer until loading completes. The metadata check must not cause a parent rebuild or density-query log.
3. Press Load density. Cached tiles are reused and missing/expired tiles built. After completion, normally all visible tiles are cached and none need building. Capacity eviction/uncached large views are reported honestly.
4. Press Refresh now. It bypasses the tile cache. Query timing, grid zoom and SQL phase/plan information remain in status/logs. The banner no longer shows grid zoom, seconds or the color scale explanation.
5. Revisit an earlier viewport; check reuse and partial overlap in logs. After two hours, expired tiles show stale (checked each minute while the layer is enabled). Clear/import invalidates cached state; reload the displayed map following those operations.

## SFDPS local analytics

1. Select `swim_sfdps` with the working authorized queue and Home gate. Confirm `/status` has source `swim_sfdps`, `bridge_enabled: false`, `density_enabled: true`, and motion `available: true`.
2. Density starts in `/data/traffic-density/swim_sfdps/`, separate from ADS-B/TFMS histories. Enable density and inspect actual reported-position cells. Gaps between reports must stay empty. Density counts represent eligible publication snapshots, not distinct position reports.
3. Motion needs at least five independent reports spanning 60 seconds. A stationary/repeated retained report does not add motion samples. Check verbose accepted/duplicate/rejection counters and supported/warming-up/stale counts. No actual report time means rejection; observation receipt time cannot substitute.
4. Verify colors, any-label filters, Fit aircraft and popup motion measurements. Report-derived ground speed must not be taken from unverified SFDPS `actualSpeed`. Altitude is reported altitude with unspecified datum, not claimed as ADS-B barometric altitude.
5. Stop/interrupt position reports: freshness expires after 45 seconds; a subsequent observation gap over 45 seconds resets the motion segment. No derivative or primitive may span that gap. Synthetic tests validate this; live cadence/quality remains to be checked.
6. Range-bearing collection, comparison envelopes, general aircraft/density exports and raw `/motion` API remain unavailable for FAA sources. SFDPS state reaches the browser through the local viewer HTML. TFMS motion remains disabled. Check SBS and aircraft.json still work when switching back.
