# Envelope diagnostic build

Install locally over the existing app so its existing density history remains available. Enable `verbose_logging`, save and restart. Generate envelopes once. Capture `[DEBUG] Envelope diagnostics` from `request_received` through `generation_completed`, plus the surrounding Data operation entries.

The per-request `job_id` identifies each cache lookup or generation attempt. `generation_lock_acquired.wait_seconds` distinguishes waiting from rebuilding. Snapshot stages report store-lock wait, flush time, monthly database bytes/copy time, and total snapshot preparation. Aggregation reports monthly input rows and elapsed time, with progress checks every 10,000 rows (at least 10 seconds apart). Bearing processing reports unique aggregate cells and time. Cache hits are explicit. Existing Data operation logs include HTTP response completion/bytes.

This is instrumentation only: no speed improvement is claimed. Long requests can still time out on the client, and no background job or cancellation is added. Progress counters do not emit while a single SQLite operation is blocked. FAA restrictions are unchanged. Logs contain no aircraft identity or coordinates. Disable verbose logging and restart after collecting results.
